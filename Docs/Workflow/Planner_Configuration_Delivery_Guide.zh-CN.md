# 策划配置交付指南

## 目的

功能交付不仅要能运行，还要让策划能在不改代码、不理解底层实现的前提下制作内容和调整体验。本指南适用于所有新增或修改策划配置的功能；配置代码、Inspector 和说明文档必须作为同一份交付物更新。

## 功能设计时的配置判断

开始实现前，先列出该功能中可能需要反复调整的业务决策：数值、触发条件、行为阶段、招式/内容编排、表现资源、音效、镜头、掉落或关卡参数。能够由策划稳定理解并在不同内容间复用的决策，应开放为配置；只服务于工程实现、会破坏合同或难以安全调试的细节，不应开放。

优先扩展已有的配置入口和引用链，避免同一功能出现两套来源。若决定不开放某项配置，必须在功能交付中写明原因，例如“仅为运行时缓存”“需要代码级不变量”或“当前样板尚未验证”。

## 配置设计要求

- 以策划工作流组织字段，而非按代码类成员顺序堆放。将同一决策所需的字段放在一起，并提供合理默认值。
- 每个开放字段必须有中文显示名和准确说明，说明基于实际运行数据流，不能承诺尚未实现的能力。
- 明确字段的所有权、数据类型、单位、默认值、取值范围或枚举、依赖/前置条件、何时读取以及会改变什么结果。
- 保留已有序列化字段名和 YAML 键；通过显示层本地化，避免为中文化进行破坏性重命名。
- 默认不向策划开放工程容量、LayerMask、物理或命中盒细节、对象池、运行时状态、缓存和其他技术实现参数。

## 配置说明文档的最低内容

每项功能的配置说明应放在 `Docs/Workflow/`，文件名使用 `<Feature>_Configuration.zh-CN.md`；也可以在已有且明确属于该功能的稳定说明文档中更新相同内容。文档至少包含以下章节。

| 章节 | 必须说明的内容 |
|---|---|
| 目标与适用范围 | 这套配置解决什么问题、适用于哪些内容、明确不覆盖什么。 |
| 配置入口与资产位置 | 从哪个场景、总配置或菜单进入；资产目录、主入口资产和保存位置。 |
| 引用关系 | 配置资产之间的引用顺序、哪些资产必须成对出现、运行时由谁读取。 |
| 制作步骤 | 从创建资产、填写字段、绑定资源到安装进场景/遭遇的完整顺序。 |
| 字段说明 | 每个开放字段的中文名、序列化字段名、类型、单位、默认值、有效范围、前置条件、实际效果和常见误配。 |
| 示例 | 至少给出一份可复用的样例配置，以及它在游戏中的预期表现。 |
| 验收与交接 | 可做的最小技术检查；需要主管试玩/判断的项目按 `Testing_Handoff_Policy.zh-CN.md` 列表移交。 |

## 字段说明表模板

| 配置组 | 中文名称 | 字段名 | 类型/单位 | 默认值与范围 | 生效条件与实际效果 | 常见误配 |
|---|---|---|---|---|---|---|
| 示例：攻击预警 | 预警时长 | `telegraphTicks` | int / Tick | 30；大于等于 0 | 招式进入攻击载荷前的可读时间 | 设为 0 会取消预警，不应用于需要反应的攻击 |

## 交付检查

- [ ] 已确认哪些业务决策由策划配置，哪些明确不开放。
- [ ] 已复用或清晰扩展唯一配置入口，没有平行配置链。
- [ ] Inspector/配置界面的显示名、说明、单位和约束与实际逻辑一致。
- [ ] 配置说明文档已同步更新，且含入口、步骤、字段表与样例。
- [ ] 需要人工体验判断的项已移入主管试玩表，未被描述为 Agent 已验收。
